# CP22 standalone issuance client

BUILD only; no execution or broadcast approval is implied. This CLI must never be imported by the web service. It only prepares the fixed deployment's first `issue(operationId, batchId, [voucherId])` of exactly one voucher on the Leader-frozen CP21 batch, attributed to the fictitious partner label from the approved config.

After fixed-source review, Leader can inspect the public plan using `.venv/bin/python -m scripts.testnet_issuance_admin plan --approved-config <approved-local-file>`. The approved file contains exactly `version:1`, `issuanceId` (unique 32-byte 0x identifier), `batchId` (frozen `0x49d1…e854`), `operator` (frozen `0xc235…8C80`), `partnerLabel`, `recipientRef` (fictitious labels, no personal data), `approved:true` and `sourceCommit` (reviewed 40-hex SHA). It contains no key, token or claim credential; neither `plan` nor `reconcile` imports the key loader. `operationId`/`voucherId` are derived deterministically as `keccak("mealforward-cp22:" ‖ issuanceId)` and `keccak("mealforward-cp22:voucher:" ‖ issuanceId ‖ ":0")`; the full calldata and both hashes are covered by `planHash`. Existing identical plans return the original record; changing issuanceId or labels is rejected.

Runtime execution requires both `execute --plan-hash <reviewed-hash> --leader-approved-plan-hash <same-reviewed-hash>`. The second explicit argument represents separately obtained Leader RUNTIME-GATE approval; it is not cryptographic authentication. All deployment, paused, ISSUER_ROLE (latest and finalized), operation payloadHash, voucher status, batch F/A/R/H/S, nonce, fee, estimate, eth_call and balance guards are repeated before loading the existing operator account. After signing, volatile paused, role, payloadHash, nonce, fee and balance guards run again before the sole send; any failure preserves consumed signing eligibility. No agent should invoke this command during BUILD. `reconcile` only reads the original transaction hash; no receipt, signing failure, lost response or failed receipt grants another attempt. A same-payload already-issued operation stops as `ISSUED_ALREADY` read-only convergence; a different payload is `INTENT_CONFLICT` and never re-parameterized.

Private state lives in `.localbackend/cp22-admin/journal.json` (0600, directory 0700). The independent `.localbackend/cp22-admin-anchor.json` must be preserved outside backups/restores of that directory. Anchor-first fsync updates and a process lock quarantine interrupted or stale restores. Missing journal/anchor never recreates eligibility. Symlinks, nonregular files, group/other permissions, oversized records and unsafe directory modes are quarantined rather than silently repaired. Restoring both the journal and external anchor together cannot be detected; this is not a supported recovery procedure. Do not delete either to start over.

SIGNING_STARTED is persisted before key loading; signed raw/hash is persisted privately; UNKNOWN with attempt=1 precedes the only send invocation. Public output omits raw transaction and exception objects. Reconcile validates original transaction, canonical receipt, the exact Issued event, finalized block and `getOperation`/`getVoucher`/`getBatch` before FINALIZED_SUCCESS.

Offline verification: `.venv/bin/python -m unittest tests.test_testnet_issuance_admin -q`. Tests use temporary directories, a deterministic synthetic account and fake RPC. No live key loading, network or transaction is needed.
