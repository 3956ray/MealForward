# MealForward（留膳）· 可操作业务测试清单

**环境：** https://mealforward-d1-offchain-staging.mealforward-lab-3956ray.workers.dev/

**级别：** 独立 Cloudflare Workers + D1 服务端持久化的 **Off-chain Staging**。这不是 CP30 主运行环境，不会连接旧的 7 USDC 资金，不是 Monad Testnet 智能合约演练。所有页面明确标记“模拟”，不可据此声称资金到账。

## 用户测试前先了解

- 推荐手机 Chrome / Safari 打开；也可用桌面 Chrome。
- 页面顶部必须显示 **STAGING · OFF-CHAIN ONLY**；不能要求 MetaMask 签名、Approve、USDC、钱包私钥或助记词。
- 点击身份栏的「商家 / 资助者 / 领取者」可在**同一个浏览器**切换三个测试角色。首次切换角色会创建独立的随机测试身份，之后这个浏览器会保留这些身份令牌。
- **不要清除浏览器网站数据**，否则会创建新测试身份。D1 原记录仍保留，但旧身份无法在当前页面自动恢复。
- 目前不支持跨浏览器导入同一测试身份；不同手机打开会创建不同测试角色。D1 业务记录对测试身份共享查看以方便联调，因此**请勿输入真实个人资料**。
- 测试假金额、餐券 ID、结果可以保留在测试库；不会生成链上 Tx Hash、真实 NFT、资金余额或实际商家付款。

## 最小负面测试

- [ ] 商家在未 Check 时直接点击 Lock：应拒绝，并显示 INVALID_TRANSITION。
- [ ] 同一券第二次 Check、Lock、Report 或 Settle：应该拒绝重复操作。
- [ ] 数量只有 1 份的订单，被领取后再次点击领券：应拒绝 NO_MEALS_REMAIN。
- [ ] 刷新页面后原 D1 记录没有丢失。
- [ ] 退出/切换浏览器身份不影响其他角色的 D1 订单，但新的测试身份与旧身份不同。
- [ ] 全流程没有真实钱包弹窗、USDC 转账、Approve、链上交易哈希或误导性的成功宣称。

## 已由 GitHub Actions 远程完成的测试

自动化脚本 `staging-d1/smoke-live.mjs` 对**公网 Worker**发送真实 HTTP 请求：

- GET /health 和首页 HTML；角色 UI 标记完整。
- 建店→模拟 Fund→模拟 Issue→Check→Lock→Report→模拟 Settle。
- 非商家权限、跨商家核销、乱序核销、重复结算及超额领取拒绝。
- **6 位领取者并发领取最后 1 份：只能生成 1 张券。**
- 全部记录从 Cloudflare D1 再次读取得到，不是浏览器内存假记录。

CI 脚本创建以 `CI Staging Kitchen` 为名的合成数据，只是测试记录。不会触碰原 CP30。

## 尚未实现的真实链上验收

这份用户列表只对应**Off-chain Staging**。下一步要另外构建安全的 Monad Testnet 环境，并实际检查：

1. MetaMask 原生登录 + Monad 10143 连接和测试 USDC 余额。
2. 独立新测试合约/escrow 的部署记录；用户钱包 Approve（如需）及真正 Fund 的 hash、receipt、finalized 状态。
3. 后端 Issue 真券、链上凭证或授权、原钱包/受助者身份隔离。
4. 商家 Check / Lock / Report、真实 receipt 对账。
5. 商家真实 Settle 交易，按资产金额与链上收款钱包验证；不得把 SQL 状态 SETTLED 冒充到账。

原 CP30 初始化后的 Journal 及其 COMMITTED-but-unfinished 事务**不可擅自启动、迁移、恢复或重放**。
