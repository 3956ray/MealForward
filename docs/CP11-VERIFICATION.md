# CP11 本地多券与部分完成验证

日期：2026-09-30。开发基线 `8c3b12656fc3c6fbd4d0f77903f44f6fa560db7c`，分支 `codex/mcpay-local-mvp`；本文件随交付提交固定。仅本地虚构DU、机构、门店与券，无推送、部署、真实账号、链或数据。

## 交付行为

- P07一次确认N=1–20张独立单份券。服务端事务校验资格/渠道/quota/报价规则/批次/暂停/A−L；全部创建才扣N额度、A→R。原intent绑定完整发行快照，同键改参数冲突，不重复预留。
- 发行结果以私有原operation关联N券。丢失响应时保存本地待核引用，只读查原intent/结果；没有服务端编号时不冒充P03编号。查不到仍阻断，恢复原结果不POST。
- P08选择原发行，每次只主动展开一张邀请；默认无secret输入，跨页/换角色/重查收起。逐券交付失败可分享同一券；不批量复制、发送或核销。
- P09/P10原店员主动建组、逐码预检并加入；组只保存非秘密券索引，不含机构发行组/ref/短码。现场仅出示2券时组只见2券。未锁项重开需要新码，已有锁/声明/申报由服务端恢复。旧单券处理记录仍可见，不强制历史记录补组。
- CP10 report/settle门控保留，并用于UI锁请求丢响应恢复；P03成功发行提供回原P08入口。各券独立继续，未知只查原操作。

## 本轮亲测

### 后端与构建

`python3 -m unittest discover -s tests -v`：**14/14通过**。保留CP10原8项，新增6项覆盖：

- 3个独立券与secret、300DU准确预留、只读intent恢复、发行集合权限与默认无秘密DTO。
- 非法数量（含bool/小数）、额度不足、A−L不足、旧价格/规则拒绝；第2张券插入前SQLite故障触发整笔回滚，券/额度/账/发行记录不部分提交。
- 不同intent竞争同一预算/额度只能安全成功；同intent并发两请求返回同一3券集合。
- 本人处理组只含主动加入2券；重复加入不增计数；其他店员不能读/加组；仅voucher_id不能拿锁；重新授权后恢复原组及UNKNOWN状态。
- CP10数据库重建后连续两次init，七张旧表内容不变、历史发行只关联一次。

`npm run build`：TypeScript及Vite通过；未新增依赖或外部资产。`git diff --check`通过。

## 剩余限制

- 未到服务端且没有原记录的发行保持保守阻断，本CP无人工强制解锁/行政恢复；不靠自动reset充当恢复。
- 标签页pending存储不等于跨设备恰好一次。服务端同intent参数绑定及事务防超预算仍是权威；不同意图仍要明确授权与额度校验。
- 门店组是工作恢复索引，不是家庭档案/资格证明；仍仅一虚构机构、一店。新schema迁移不会替真实历史数据补造家庭归属。
- 跨客户端清码仍为2秒轮询间隔+响应，探针3秒客户端超时，不承诺固定可见延迟。公账真人数据侧信道、渐变对比度人工核验、真实身份/供餐/链上验证仍未关闭。
