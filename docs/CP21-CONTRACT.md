## Fixed-SHA review corrections

P2-01: budget validation remains strict by default (including admin use). Only the observer separates original transaction identity validation from fee/gas limit classification; mismatched sender/target/chain/nonce/calldata/value/type cannot enter the continued observation path. A budget-only legacy halt can resume read-only tracking, with consumed eligibility retained. Neither a normal result nor an RPC recovery clears budgetViolation. No retry/signing path is added.

P2-02: finalizedReceipt fixes execution status, block number/hash, and actual gas fee. A differing receipt is persisted as receiptConflict and FINALITY_CONFLICT/HALTED without changing previous receipt fields or accounting. Both success→revert and revert→success are conflicts. Known earlier CP21 finalized states can supply this fact when reading an old record; ambiguous historical finalized state is quarantined. UI labels conflicting/stale accounting as historical evidence rather than mixing it with a new outcome.

P2-03: schema-valid HTTP200 does not imply fresh observation. operation.errorCode other than the persistent budget-only warning marks data stale and exposes the error at the page top. Historical finalized facts/accounting remain visible with explicit wording. A completed subsequent check clears transient error/staleness; budget warnings remain. A previously finalized transaction/receipt temporarily missing from RPC is likewise an unavailable read, not a fresh result.
