## 2026-10-21 T1-B 真人失败与签名协议修复

受测用户成功在已部署的 Monad Testnet 10143 上读取原 Escrow：7 Test USDC/份、零 funded units、10 lifetime units remaining、Escrow 测试 USDC 余额 0。受测 MetaMask 钱包为 T0 已登记的 Quote Authority（公开链上地址）；该地址显示测试 MON 与测试 USDC 足够，Allowance=0，无交易。用户点击 Quote Authority harmless T1RoleControl EIP-712 challenge 并在 MetaMask 中看到 Account 2 签名确认框，但是原页面返回 `ROLE_SIGNER_MISMATCH`；旧账户无效提示残留。

**已复现的根因是浏览器签名请求的协议编码：** 旧 `pilot/t1-readiness.mjs` 送出的 `eth_signTypedData_v4` JSON 只含 `types.T1RoleControl`，**缺少 `types.EIP712Domain`**，但本地 ethers `verifyTypedData` 使用完整 Domain（name、version、chainId、verifyingContract）。MetaMask 的 V4 实现会将缺少的 EIP712Domain 类型视为无字段的空 Domain，因此它签署的 digest 与 ethers 期望的完整 Domain 不同。这个结果不能推导出用户不掌握 Quote 钱包的私钥。

本轮修复：
- `pilot/t1-proof.mjs` 增加 `buildMetaMaskQuoteControlPayload`，显式为 RPC JSON 添加标准 `EIP712Domain` 四字段；既有原业务 FundingQuote Domain、原 StoreEscrow、公开 Quote 地址均未改动。
- 本地 `verifyTypedData` 仍使用原 Custom Type 与完整 Domain；仅对真正的固定 Quote Authority 认定 PASS。
- 修复钱包重连后旧 `quoteInfo` 提示残留、签名过程中 MetaMask 账户/网络变化时的失效检查；异常仅向页面提示可公开的预期地址与按指定 Domain 恢复的地址，**不存储、传输、记录或请求用户分享原始签名**。
- 新增 `@metamask/eth-sig-util@9.0.0` **仅作为 CI 测试依赖**，用临时测试密钥复现旧实现的错误恢复地址，并证明修复后的 MetaMask V4 EIP-712 Hash 与 ethers.js TypedDataEncoder Hash 逐字节一致。
- GitHub Actions 2026-10-21 [T1 browser test PASS](https://github.com/3956ray/MealForward/actions/runs/39595340446)，12/12，包括真实 MetaMask V4 算法交叉测试。旧 T0 只读/独立部署测试仍通过。
