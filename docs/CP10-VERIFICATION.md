# CP10 本地 UX 验证记录

目标分支：`codex/mcpay-local-mvp`。范围是 `#/P01`–`#/P14` 的本地虚构 UI、一个领取者只读状态接口及其边界测试；没有真实账户、交易、链连接、对外发送或部署。

## 行为与边界

- P05 在绘制前清除邀请 fragment，并只在本次内存保留待交换秘密。浏览器独立会话实测：访问 `#/P05/<secret>` 后地址为 `#/P05`，DOM 中没有 secret、QR、短码或领取 token；网络中没有 `/api/invite/exchange`。点击“查看餐券”后才出现一次 POST 和单券视图。无效邀请失败后无 QR、无 token、无自动重试。
- 离开 P05、返回、硬刷新及新邀请到达都隐藏旧码；返回与硬刷新落在“需要原私密邀请”。短码到期、手动重查开始、可见页只读状态检查失败、他处锁券、交付失效、暂停或会话失权时卸载 QR。两店员/持券者的独立会话中，甲锁券后，持券页在下一次状态检查中自动撤掉 QR 和短码；服务端同一刻已拒绝旧码。前端每 2 秒发起只读检查，并给单次请求 3 秒超时；这不是瞬时跨客户端通知。后台标签页变为隐藏时前端立即清码，返回后需手动重查。
- P02 选择 UNKNOWN 后进入 P03；浏览器返回 P02 时不存在“确认模拟支持”按钮，只提供原 ID 查询。模拟 `/api/state` 刷新失败后同样保持该阻断；SUCCESS 的服务端操作记录在硬刷新后的 P02 也阻断再提交。P03 UNKNOWN 首屏显示“结果待核，只查原操作”；查询时间明确是“本机显示”，并写明不是服务端确认时间。
- P09 两个店员先对同一码预检；甲取得唯一处理权后，乙的锁请求被拒且旧预检可写控件撤掉。P09 预检有效后离开再返回，旧绿色结果与锁按钮也不复活。P10 在确认锁前仅显示确认动作；申报明确失败保留原 ID，后续明确成功才 R→H。P11 结算失败保留 H 和原 ID；再次模拟 UNKNOWN 后结算按钮消失，只剩原付款查询。预置暂停时支持、发券和新结算按钮被禁用，旧 H 仍可查。

## 验证执行

- `python3 -m unittest discover -s tests -v`：8 项通过，其中新增只读探针权限、状态与不重发码测试。
- `npm run build`：TypeScript 检查和 Vite 构建通过。`git diff --check` 通过。
- Chromium 独立会话在 320×720、390×760、1280×800 跑 P01/P04、P06–P08、邀请→P05→P12、P09–P11。页面无水平溢出；320px 首页 CTA 底部约 633px，P02 提交按钮底部约 703px，P07 首个发券按钮顶部约 631px，P11 结算按钮顶部约 548px；390px P10 确认按钮顶部约 485px。跨页及后退将焦点交给主内容、标题可见；页内查询不拉回顶部。键盘 Enter 可导航，Tab 后有实线焦点环。
- 200% CSS 缩放模拟时 P11 文本与操作仍可阅读，`scrollWidth === clientWidth`；系统 `prefers-reduced-motion` 下公开页入场动画为 `none`。以 Chrome DevTools Protocol 开启 4× CPU 限速后，P01→P04 仍完成路由、主内容焦点和标题展示，随后恢复正常速度。
- axe-core 在修复公告条 landmark 后对 320px P01 检查为 0 明确违规；渐变背景令自动对比度判定仍有 incomplete 项，未宣称其已自动通过。项目保留本机忽略目录 `evidence/` 的 P01/P04/P05/P10/P11 截图，用于同机复核；P05 截图含虚构短码，不纳入 Git。
- 复核追加：同一帧连续两次点 P05 重查，页面最终短码仍通过服务端店员预检；持券者 P12 的模拟求助提交后，本人案件列表出现且页面没有 QR。模拟延迟领取者写请求响应，在离开 P05 后放行旧响应，P12 仍没有 QR 或旧提示。独立技术审查发现的取码并发、P03 查询串号、P02 刷新失败回退、P09 旧预检和已结算文案问题均已修复；复核无新阻断问题。
- 接班开发只读审阅后的回归：SUCCESS 的服务端支持记录在 P02 硬刷新后仍撤下提交按钮；旧 P05 状态请求保留一笔模拟 401，在打开新邀请并取得新 token 后再放行，新的 token 和 QR 均保持。前端写请求响应按会话/路由代数丢弃，避免离页后继续重查旧券或改写导航。

## 依赖、动效和剩余限制

### Leader 收尾：失败重查后的失效检查

在 `perform` 的失败恢复 `await refresh(token)` 后再次核对 `actionEpoch` 与 `precheckEpoch`，过期请求不再写回旧错误。浏览器受控延迟真实无效短码请求后的 `/api/state` 响应：等待中从 P09 离开到 P12，再放行响应，P12 无旧错误且求助按钮恢复可用；同页等待中将短码改为 `CHANGED` 后放行，输入保留、无旧错误、预检按钮恢复可用。保留 `finally` 释放 busy：本次请求仍占有忙状态，过期返回也须解除；等待期间写按钮保持禁用。

### Leader 阻断修复：申报与结算在网络不确定时只读待核

P10 `report`、P11 `settle` 在 POST 前保存按 actor/action/voucher 隔离的标签页 `sessionStorage` 待核记录。返回 UNKNOWN、丢失响应、状态查询失败或原操作查询失败时，旧 `handoff` / `reported` 缓存不能恢复写按钮；操作函数也检查同一门控。跨页、刷新和同角色重新进入保留记录，成功重置虚构样例才统一清除。

已知原 ID 时提供 P03 原操作链接；响应丢失时提供“重查服务端状态”，从当前券记录取得候选 ID，再只读查询原操作，核对 actor/action/target/intent。只有匹配原操作明确 SUCCESS/FAILED，且本次权威状态同时确认对应 ID 与结果，才与新状态一起解除门控。UNKNOWN 一直待核；状态不存在原操作不能证明 POST 未执行，因此继续保守阻断，不自动补发。明确失败后允许用户主动新试，同时移除旧 intent 缓存，避免把主动新试误当旧失败操作回放。

故障注入使用真实本地 API 建立单券 handoff / reported 前置状态，在浏览器拦截 fetch：对 `/api/state` 抛出网络错误；响应丢失分支先让 `/api/act` 在服务器执行，再丢弃该响应。各项都验证旧卡片无写按钮、离页返回仍待核；恢复 GET 后核对原 ID，并进入 P03 查询。

| 动作 | 注入结果 | 恢复后的行为 | 写请求计数 |
| --- | --- | --- | --- |
| report / settle（各一项） | UNKNOWN + state 失败 | 保留待核、P03 查询原 ID | 各 1 次 |
| report / settle（各一项） | SUCCESS 响应丢失 + state 失败 | 恢复原 ID，确认终态后显示已完成 | 各 1 次 |
| report / settle（各一项） | FAILED 响应丢失 + state 失败 | 查询确认失败后，用户主动同结果新试得到新 ID | 各 2 次，第二次为显式点击 |

六项浏览器故障回归通过；320×720 与 1280×800 的 P11 待核页无横向溢出，硬刷新后仍仅提供查询入口。最终代码的 TypeScript/Vite 构建、8 项后端测试及 `git diff --check` 通过。本机可复核脚本和输出保留于忽略目录 `evidence/cp10-guard-{setup,check}.js`、`evidence/cp10-guard-run.sh`、`evidence/cp10-guard-results.txt`。这些门控只补齐本机标签页 UI，不替代服务端权限、防重和状态权威；若 POST 未到服务端且一直没有匹配原操作，本轮不提供绕过待核的写入口。

没有新增第三方包或资产；公开 P01/P04/P14 只用 210ms、8px 的 CSS 入场动效，按钮反馈 120ms；私密视图和写状态不做退出动画。无需 Motion 或新增许可证记录。

跨客户端锁券从仍可见的持券页卸载需等待下一次 2 秒间隔的检查及其响应；单次请求设置 3 秒客户端超时，实际可见延迟仍受浏览器调度影响，不能承诺固定上限。轮询响应前服务端已经拒绝该码。渐变背景上的文字对比度需要人工复核。证据仅限本机虚构样例，不代表真实身份、链上交易或生产环境验收。
