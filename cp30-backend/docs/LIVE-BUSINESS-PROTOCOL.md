# One-store real business protocol — source BUILD

All source remains unexecuted against PG, identity, RPC, keys or wallets.

`c1_live_private` owns verified registered stores, complete finalized facts,
reviews, original intents, wallet attempts, private voucher ownership, short-lived
credentials and complete original receipt proofs. No synthetic source/model/009
transition is called. `live_api` is authenticated fixed business dispatch;
`live_material`, `live_prepare`, `live_result`, `live_projection` and
`live_approval` are separate private observer/runtime commands. Every command
carries the existing PgRuntimeLedger controller ticket. The single ledger's
material includes live rows and runtime_attempt floors include monotonic live
revisions, so the external controller seals projection and token changes too.

Read transaction → detached registered profile/original/CAS → actual codec or
observer outside transaction → short serializable write rechecks guards, exact
original, registered binding, current session/store/role, revision and watermark.
Only trusted private observer writes facts/proofs. Newer snapshot replaces facts;
same-height forks close; older receipt proves its original without replacing newer
facts. Full original proof is retained and receipt locator conflicts close.

Support freezes quoteId/payer/meal/version/terms/quantity/amount/deadline; quote
signature is a private authority original result. Approve/fund each retain the
original preparation before wallet submission; attempted without a hash remains
UNKNOWN, never automatically sent again. Hash is only a locator. Original approve
receipt plus actual finalized allowance enables fund, never marks it funded. Only
original finalized fund proof establishes funded counts.

Issue fixes candidate unitSeq/nextGeneration/terms/deadline from complete facts;
recipient ownership is attached only from its original finalized issue proof.
Recover/display secrets are stored as hashes and bound to real session/credential
and voucher epochs. Check is a preflight. Explicit lock consumes display once,
then explicit same-owner handover creates markHandover followed by its original
report. All pending operations use original IDs/hashes; unknown never re-signs.
Tokens are unusable while lock/handover pending and after lock/marker/use/expiry.
Owner settlement is an original wallet attempt; only original finalized settle
proof advances paid amounts, while pending remains pending.

First-run extras (refund, arbitrary menu changes, controls/admin) are closed.
No public flags can fabricate approval, signed raw, candidate, snapshot or success.
Independent epoch adoption/full-app startup remain separate readiness work.
